# King VPN v8.5 — Smart Pilot UI

مخزن سورس King VPN برای کار با GitHub و ساخت اندروید از طریق GitHub Actions.

> **وضعیت:** این مخزن سورس برنامه و اسکریپت تولید پروژه Flutter/Android را نگه می‌دارد. فایل APK از قبل داخل مخزن نیست؛ workflow آن را در GitHub Actions می‌سازد.

## ویژگی‌های بسته

- حفظ ابزارها و اسکنرهای موجود در سورس ارسالی؛ از جمله DNS، IP، SNI، پورت، نت ملی، سرور شخصی، خرید سرور، کانال‌های تلگرامی، Cloudflare/CDN، Reality و WebSocket.
- حذف فقط سه کاشی ابزار از صفحه ابزارها: «پروفایل‌ها»، «حالت شبکه» و «تست کامل خودکار». تب ناوبری پایین صفحه و سایر صفحات/ماژول‌ها حذف نشده‌اند.
- خلبان محلی «خلبان هوشمند ∞» پیش از اتصال نوع شبکه را با شواهد موجود تشخیص می‌دهد و در حالت ملی، سلامت داخلی را مستقل از سرویس‌های جهانی ارزیابی می‌کند. ترمیم کد اجرایی از مسیر امن گزارش/پچ/CI انجام می‌شود، نه با بازنویسی APK نصب‌شده.
- رنگ‌بندی یکپارچه و کم‌رنگ بر پایه ذغالی، سرمه‌ای، طلایی مات و متن روشن؛ از رنگ‌های تند و رنگین‌کمانی در اجزای اصلی رابط پرهیز شده است.

## ساخت APK در GitHub

1. یک repository در GitHub بساز و محتویات این پوشه را در ریشه repository بارگذاری کن.
2. از تب **Actions**، گردش کار **King VPN Android CI** را انتخاب کن.
3. روی **Run workflow** بزن؛ همچنین push به شاخه `main` یا `master` و Pull Request باعث اجرای خودکار می‌شود.
4. پس از پایان موفق، در بخش **Artifacts** فایل APK آزمایشی `king-vpn-debug-*` را دریافت کن.

این workflow برای ساخت APK آزمایشی به کلید امضای شخصی نیاز ندارد. APK خروجی debug است و برای انتشار عمومی/فروشگاه باید با کلید release اختصاصی خودت امضا شود. کلیدها و رمزهای امضا را هرگز داخل Git قرار نده.

## ساخت محلی

نیازمندی‌ها: Flutter stable، Android SDK، Java 17 و Python 3.

اسکریپت workflow ابتدا یک میزبان Flutter اندروید در `build_app/` تولید می‌کند، سورس `lib/` را در آن کپی می‌کند، وابستگی‌ها را نصب می‌کند و سپس `prepare_android.py` و `patch_plugin.py` را اجرا می‌کند. برای اجرای همان مسیر در محیط محلی، مراحل متناظر workflow را دنبال کن.

## ساختار مهم

- `lib/` — سورس Dart برنامه و ابزارها
- `android_src/` — فایل‌های اختصاصی Android/Java/Kotlin که در مرحله آماده‌سازی کپی می‌شوند
- `plugin_source_reference/` — سورس مرجع پلاگین ارسالی برای بررسی؛ در زمان build به‌عنوان جایگزین خودکار dependency استفاده نمی‌شود
- `test/` — تست‌های واحد موجود
- `.github/workflows/build.yml` — ساخت خودکار APK در GitHub Actions
- `prepare_android.py` — آماده‌سازی Manifest، Gradle و فایل‌های Native
- `patch_plugin.py` — اصلاح سازگاری پلاگین V2Ray در محیط build

## معماری خلبان هوشمند ∞ و خودترمیمی

- مسیر اتصال موجود Xray/V2Ray حفظ شده است؛ هیچ هسته‌ی اضافی یا placeholder مربوط به موتور دوم در این نسخه نگهداری نمی‌شود.
- `lib/network_health.dart` سلامت Domestic و Global را جدا نگه می‌دارد؛ قطع اینترنت جهانی به‌تنهایی سلامت مسیر داخلی را باطل نمی‌کند. خلبان و watchdog برای حالت ملی از مقصدهای داخلی استفاده می‌کنند.
- `lib/self_repair_policy.dart` سیاست تعمیر امن، rollback و دروازه پذیرش Patch کد را تعریف می‌کند. برنامه نصب‌شده سورس اجرایی خود را درجا بازنویسی نمی‌کند.
- `tools/diagnose_build.py` گزارش خطاهای build را برای تشخیص ریشه‌ای آماده می‌کند؛ CI هنگام شکست، artifact عیب‌یابی تولید می‌کند. `lib/errjournal.dart` نیز گزارش runtime محدود و پاک‌سازی‌شده از لینک کانفیگ/شناسه/credential می‌سازد.
- `tools/patch_gate.py` ساختار Patchهای پیشنهادی را از نظر مسیرهای خطرناک، فایل‌های محافظت‌شده، افشای secret و اندازه تغییر بررسی می‌کند.
- `tools/repair_orchestrator.py` Patch پیشنهادی را فقط در یک کپی موقت اعمال می‌کند و پس از تست، تحلیل ایستا و بیلد موفق، آن را به‌عنوان Patch تأییدشده صادر می‌کند؛ سورس اصلی را تغییر نمی‌دهد.
  نمونه اجرا: `python3 tools/repair_orchestrator.py --patch candidate.patch --output verified-repair.patch`. این فرمان به Git و Flutter SDK نیاز دارد.
- نقشه کامل نیازمندی‌ها و معیارهای پذیرش در `docs/KING_VPN_INFINITY_ROADMAP_FA.md` است؛ وضعیت واقعی تغییرات و محدودیت‌های تست در `docs/IMPLEMENTATION_STATUS_FA.md` ثبت می‌شود.

## نکات مهم پیش از انتشار

- در این محیط Flutter/Dart و Android SDK اجرا نشدند؛ بنابراین Build واقعی و تست روی دستگاه تأیید نشده‌اند. نتیجه نهایی را از GitHub Actions بررسی کن.
- بعضی قابلیت‌ها به سرویس‌های بیرونی، حساب Cloudflare، سهمیه ارائه‌دهندگان یا تنظیمات سمت سرور وابسته‌اند؛ «نامحدود» بودن از طرف اپ تضمین نمی‌شود.
- فایل‌های `plugin_source_reference/` برای ممیزی و مرجع‌اند؛ مجوز و شرایط بازتوزیع وابستگی‌ها را پیش از انتشار عمومی بررسی کن.
- این مخزن مجوز استفاده/بازنشر جداگانه‌ای اعطا نمی‌کند؛ حقوق سورس متعلق به صاحب آن است مگر اینکه مجوز مستقلی اضافه شود.
- قبل از عمومی‌کردن repository، کلیدهای API، توکن‌ها، آدرس‌های خصوصی و اطلاعات سرور را از سورس و تاریخچه Git پاک‌سازی کن.
