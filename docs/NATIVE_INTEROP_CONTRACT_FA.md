# قرارداد بین‌زبانی هسته بومی KING VPN

## دامنه

این سند قرارداد فعلی ارتباط بین موتور Dart/Flutter و کتابخانه بومی Rust را ثبت می‌کند. این قرارداد بخشی از معماری چندزبانه KING VPN است؛ زبان‌ها بر اساس مسئولیت واقعی انتخاب می‌شوند و قرار نیست همه ماژول‌ها به یک زبان منتقل شوند.

## نقشه مسئولیت‌های موجود

| زبان | محل فعلی | مسئولیت |
|---|---|---|
| Dart / Flutter | `lib/` | رابط کاربری، منطق برنامه و مسیر پشتیبان پردازش |
| Rust | `native/king_native_core/` | شتاب‌دهی اختیاری پردازش batch آدرس‌های IPv4/IPv6 |
| Kotlin | `android_src/MainActivity.kt` | اتصال Flutter به APIهای Android و مدیریت کانال‌های پلتفرم |
| Java | `android_src/KingVpnService.java` و `KingDiag.java` | چرخه عمر سرویس VPN، مدیریت هسته و تشخیص خطا |
| Python | `tools/` و `test/` | ابزارهای مهندسی، اعتبارسنجی منبع و آزمون قراردادها |

وجود زبان‌های دیگر مانند Go، TypeScript، C/C++ یا SQL به‌تنهایی هدف نیست. ورود هر فناوری جدید باید یک نیاز مشخص، مزیت قابل‌اندازه‌گیری، مرز مالکیت روشن و مسیر ساخت و آزمون مستقل داشته باشد.

## قرارداد Rust FFI

- نام کتابخانه Android: `libking_native_core.so`
- نماد نسخه ABI: `king_native_core_abi_version() -> u32`
- نسخه مورد انتظار فعلی در Dart: `KingNativeAccel.expectedNativeAbiVersion = 1`
- نماد پردازش: `king_expand_range_batch`
- ورودی‌ها: رشته‌های UTF-8 خاتمه‌یافته با NUL برای محدوده و cursor، اندازه batch و بافر خروجی قابل‌نوشتن.
- خروجی: تعداد بایت نوشته‌شده؛ `-1` برای ورودی/اشاره‌گر/حد نامعتبر و `-2` برای کوچک بودن بافر.
- قالب خروجی UTF-8: cursor بعدی در خط اول و سپس یک IP در هر خط.
- حداکثر batch در مرز FFI برابر 8192 است.

## قانون سازگاری و fallback

1. Dart ابتدا کتابخانه را بارگذاری و نماد ABI را می‌خواند.
2. تا زمانی که نسخه دقیقاً با نسخه مورد انتظار برابر نباشد، نماد پردازش resolve یا فراخوانی نمی‌شود.
3. نبود کتابخانه، نبود نماد نسخه، ناسازگاری نسخه یا خطای بارگذاری باید مسیر Rust را غیرفعال کند و مسیر Dart موجود را حفظ کند.
4. حتی پس از اعتبارسنجی ABI، خروجی native همچنان اعتبارسنجی می‌شود؛ شکست خروجی به معنای استفاده از نتیجه نامعتبر نیست.
5. انتخاب Rust برای پردازش همچنان منوط به benchmark و برابری نتیجه با Dart است؛ بررسی ABI به‌تنهایی مجوز انتخاب Rust نیست.

## قواعد تغییر نسخه

- تغییر ناسازگار در امضای C، قرارداد حافظه، کدهای بازگشتی یا قالب wire باید نسخه ABI را افزایش دهد.
- در یک تغییر سازگار، نسخه می‌تواند ثابت بماند؛ اما آزمون‌های Rust، Dart و آزمون ایستای Python باید هم‌زمان به‌روز باشند.
- نماد نسخه باید در کتابخانه بومی export شود و قبل از نماد پردازش بررسی شود.
- هیچ تغییر ABI نباید fallback موجود Dart را حذف کند.
- تغییر قرارداد باید در همین سند ثبت شود و روی Android arm64 در CI ساخته شود.

## اعتبارسنجی خودکار

CI از آزمون‌های Python برای مقایسه نسخه اعلام‌شده در Rust و Dart و کنترل ترتیب handshake استفاده می‌کند. آزمون‌های Rust، تست‌های Flutter و ساخت Android arm64 نیز قرارداد اجرایی را در سطوح مربوطه بررسی می‌کنند.

موفقیت CI به‌تنهایی تست اتصال VPN روی دستگاه فیزیکی یا اثبات بهبود سرعت نیست.
