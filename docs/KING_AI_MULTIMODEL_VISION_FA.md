# KING AI — موتور چندمدلی و تحلیل تصویر

تاریخ طراحی و پیاده‌سازی اولیه: 2026-11-25

## هدف

KING AI علاوه بر مدل محلی، بتواند با رضایت روشن کاربر از چند ارائه‌دهندهٔ ابری برای تحلیل متن، کدنویسی و تصویر کمک بگیرد. مدل محلی مسیر آفلاین باقی می‌ماند؛ اتصال ابری جایگزین اجباری آن نیست.

## ارائه‌دهندگان فعلی در لایهٔ اتصال

| ارائه‌دهنده | پروتکل | تصویر |
|---|---|---|
| OpenAI / ChatGPT | Chat Completions | وابسته به مدل |
| Claude / Anthropic | Messages API | وابسته به مدل |
| Gemini | generateContent | وابسته به مدل |
| Kimi / Moonshot | OpenAI-compatible | وابسته به مدل و دسترسی حساب |
| DeepSeek | OpenAI-compatible | در این پروفایل فقط متن |
| Qwen / DashScope | OpenAI-compatible | وابسته به مدل |
| OpenRouter | OpenAI-compatible | وابسته به مدل انتخابی |
| Groq | OpenAI-compatible | در پروفایل فعلی فقط متن |
| Cerebras Inference | OpenAI-compatible | در پروفایل فعلی فقط متن |

نام مدل‌ها پیش‌فرض و قابل‌تغییرند؛ نام، دسترسی، تعرفه و قابلیت هر مدل ممکن است از سمت ارائه‌دهنده تغییر کند. وجود یک گزینه در برنامه به معنی داشتن حساب، API key، اعتبار رایگان یا دسترسی تضمین‌شده نیست.

### Cursor

Cursor یک محیط توسعه و عامل برنامه‌نویسی است، نه یک API مدل عمومی هم‌نوع OpenAI یا Gemini. برای همین در کاتالوگ providerهای API قرار نگرفته است. یک workflow اختیاری و دستی GitHub با Cursor CLI اضافه شده که فقط در حالت Ask/read-only diff را بازبینی می‌کند و گزارش را به‌صورت artifact تحویل می‌دهد. اجرای آن به CURSOR_API_KEY در Actions Secrets نیاز دارد و هیچ‌وقت به‌طور خودکار اجرا نمی‌شود. CLI رسمی Cursor از حالت headless و Ask پشتیبانی می‌کند.

اتصال آیندهٔ Agent mode برای تولید تغییرات باید در worktree ایزوله، با مجوز جداگانه، بدون دسترسی مستقیم به main و با بازبینی KING AI انجام شود؛ استفاده از API مدل‌هایی که Cursor در IDE انتخاب می‌کند، معادل اتصال به خود Cursor نیست.

## رفتار و رضایت

- پردازش بیرونی به‌صورت پیش‌فرض خاموش است.
- ارسال سورس پروژه برای بازبینی چندمدلی یک رضایت مستقل و جداگانه دارد؛ رضایت چت/تصویر به‌تنهایی اجازه ارسال سورس نیست.
- کاربر می‌تواند رضایت پایدار را در صفحهٔ تنظیمات روشن یا خاموش کند.
- برای یک درخواست خاص نیز پنجرهٔ اجازهٔ یک‌باره نمایش داده می‌شود؛ این اجازه در secure storage ذخیره نمی‌شود و پس از بسته‌شدن برنامه باقی نمی‌ماند.
- انتخاب تصویر به‌طور خودکار به مسیر مدل تصویری هدایت می‌شود؛ تصویر به مدل محلی text-only ارسال نمی‌شود.
- مسیر ابری فقط providerهایی را انتخاب می‌کند که کلید امن و وضعیت فعال دارند.
- در خطا یا timeout، provider بعدیِ پیکربندی‌شده امتحان می‌شود؛ خطاها کوتاه و بدون نمایش Authorization header ثبت می‌شوند.

## امنیت و حریم خصوصی

- کلیدهای API با FlutterSecureStorage ذخیره می‌شوند؛ هیچ کلیدی در سورس، asset، APK یا prompt قرار نمی‌گیرد.
- کلیدهای GitHub و providerها از هم جدا هستند.
- تصاویر فقط برای همان درخواست خوانده و به API provider فرستاده می‌شوند؛ این ماژول آن‌ها را در آرشیو یا حافظهٔ پایدار خودش ذخیره نمی‌کند. کنسول مالک پیش از ارسال هشدار می‌دهد که اسکرین‌شات ممکن است کلید، UUID یا رمز داشته باشد.
- image picker تصویر گالری را با ابعاد حداکثر ۲۰۴۸ و کیفیت ۸۵ برای کاهش payload آماده می‌کند.
- ارسال تصویر و متن به سرویس بیرونی ممکن است هزینه داشته باشد و تابع سیاست نگهداری داده و حریم خصوصی همان سرویس است.
- کاربر باید برای هر provider کلید خودش را تهیه کند. گزینه‌های رایگان OpenRouter یا سایر ارائه‌دهندگان، تضمین دائمی ندارند.

## مرز پیاده‌سازی فعلی

- **IMPLEMENTED:** کاتالوگ providerها، endpointهای HTTPS ثابت، ذخیره امن کلید، انتخاب مدل، روشن/خاموش‌کردن provider، رضایت cloud و fallback متوالی.
- **IMPLEMENTED:** ساخت payloadهای متن/تصویر برای OpenAI-compatible، Anthropic و Gemini و استخراج پاسخ متنی.
- **IMPLEMENTED:** انتخاب تصویر از گالری در چت، preview پیام و ارسال به مدل تصویری پس از اجازه کاربر.
- **IMPLEMENTED:** در کنسول مالک، تصویر مرجع تنظیمات پس از احراز هویت و اجازه ارسال تحلیل می‌شود؛ تحلیل به درخواست قابلیت اضافه می‌شود تا در مسیر عادی owner-only کدنویسی و ساخت PR بررسی شود.
- **IMPLEMENTED:** اجازهٔ یک‌باره بدون تغییر رضایت پایدار.
- **IMPLEMENTED:** مسیر owner-only کدنویسی می‌تواند پس از احراز هویت مالک و دو رضایت مستقل، از همه providerهای متنی فعال بازبینی موازی بگیرد؛ پاسخ‌ها فقط توصیهٔ غیرقابل‌اعتماد هستند و مدل محلی همچنان patch را می‌سازد.
- **IMPLEMENTED:** workflow دستی Cursor CLI در حالت Ask/read-only؛ فقط گزارش artifact تولید می‌کند و هیچ فایل یا شاخه‌ای را تغییر نمی‌دهد.
- **IMPLEMENTED:** پیش از ارسال سورس، الگوهای رایج credential، لینک‌های کانفیگ VPN و UUIDها redacted می‌شوند؛ هیچ provider خارجی اجازه اعمال مستقیم patch ندارد.
- **NOT VERIFIED:** CI، تست دستگاه واقعی، آزمون درخواست با کلیدهای واقعی، هزینه/سهمیه واقعی حساب‌ها و کیفیت تحلیل عکس هنوز باید تأیید شوند.
- **NOT IMPLEMENTED:** اتصال Cursor Agent mode برای تولید patch، مدیریت کلیدها از Backend، نمایش مصرف/هزینه، streaming token UI، انتخاب مدل بر اساس benchmark و داوری چندمدلی consensus.
- **NOT IMPLEMENTED:** تولید patch نهایی به‌صورت مستقیم توسط مدل‌های ابری؛ آن‌ها فعلاً بازبین مستقل‌اند و patch را مدل محلی تولید می‌کند. چت عمومی مجوز تغییر سورس ندارد.

## مسیر بعدی

1. اجرای CI و رفع خطاهای analyzer/test/build.
2. آزمون قراردادی API هر provider با mock response؛ بدون نیاز به کلید واقعی.
3. افزودن آزمون اندازهٔ تصویر، MIME، پاسخ ناقص، timeout و fallback.
4. افزودن انتخاب provider و مدل برای هر وظیفه، سپس ارزیابی چندمدلی مستقل.
5. اتصال مرحله‌ای به مسیر owner-only کدنویسی: context حداقلی، redaction، خروجی patch ساختاریافته، بررسی سه‌مرحله‌ای، تست و PR؛ بدون merge خودکار.
6. بررسی راهکار رسمی Cursor Agent/CLI فقط در محیط توسعه/worker مناسب، نه قراردادن ابزار توسعهٔ دسکتاپ داخل APK.

این مرحله زیرساخت اتصال اولیه است و نباید به‌عنوان تیم چندهوش‌مصنوعی کامل، اتصال Cursor یا قابلیت production-ready معرفی شود.
