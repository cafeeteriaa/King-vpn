# وضعیت پیاده‌سازی King VPN — 2026-11-18

## تغییرات واقعی اعمال‌شده در سورس

- هیچ موتور اضافی به پروژه اضافه نشده است؛ مسیر اجرایی موجود Xray/V2Ray حفظ شده و هرگونه رجیستری/placeholder مربوط به موتورهای دیگر حذف شده است.
- خلبان محلی پیش از اتصال، تشخیص شبکه را اجرا می‌کند. اگر مسیر داخلی قابل دسترسی و مسیر جهانی قطع/محدود باشد، حالت ملی را انتخاب می‌کند؛ اگر شواهد نامشخص باشد، حالت قبلی را حفظ می‌کند.
- دروازه‌ی ترافیک اولیه‌ی اتصال اکنون در حالت ملی از مقصدهای داخلی استفاده می‌کند؛ DNS داخلی نیز در حالت ملی قبل از resolverهای باقی‌مانده‌ی کانفیگ قرار می‌گیرد.
- اسکن خودکار IP به IPهای دقیق موجود در کانفیگ‌ها/حافظه‌ی سرورهای موفق محدود شد؛ اسکن خودکار CIDRهای عمومی ISP/CDN، IPهای DNS ثالث، همسایگی /24، دامنه‌های عمومی نامرتبط و پیمایش همه‌ی پورت‌ها حذف شد. ابزار اسکن دستی مستقل باقی است.
- تغییر SNI دیگر TLS certificate validation را خاموش نمی‌کند و گزینه‌ی SNI با IP نامعتبر حذف/جایگزین شده است. DoH با پاسخ DNS JSON و نام پرس‌وجوی مورد انتظار اعتبارسنجی می‌شود؛ پاسخ DNS خام نیز مالک رکورد و زنجیره CNAME را بررسی می‌کند.
- محدودیت قدیمی که خلبان را همیشه از حالت ملی خارج می‌کرد حذف شد.
- watchdog در حالت ملی از مقصدهای داخلی برای سنجش عبور ترافیک استفاده می‌کند؛ شکست Google/Cloudflare/Telegram یا تست سرعت بین‌المللی به‌تنهایی باعث failover مسیر داخلی نمی‌شود.
- معیارهای Telegram و سرعت جهانی از رتبه‌بندی و تصمیم خودترمیمی در حالت ملی حذف شدند. پینگ مسیر داخلی نیز با پینگ هسته/سرور یکی گرفته نمی‌شود.
- خودترمیم پس از اقدام، فقط با CONNECTED بودن هسته موفقیت را اعلام نمی‌کند؛ عبور ترافیک واقعی از تونل و سایت‌های متناسب با حالت شبکه لازم است.
- زمان پایداری خودترمیم با هر قطع اتصال reset می‌شود تا جلسه قبلی روی جلسه جدید اثر نگذارد.
- موتور سیاست خودترمیم و دروازه Patch سورس اضافه شد: خطایابی، rollback، امضای معتبر، تست، تحلیل ایستا، محدودیت مسیر، کنترل secret و بازبینی فایل‌های Android محافظت‌شده.
- تنظیمات مسیریابی ایران، QUIC، LAN، DNS امن و RouteOnly اکنون در مسیر نهایی ساخت کانفیگ اعمال می‌شوند؛ Mux به‌صورت پیش‌فرض خاموش است و فقط با انتخاب کاربر فعال می‌شود.
- parser پلاگین در مرحله Build سخت‌سازی می‌شود: WS path رشته‌ای، VMess URL-safe Base64 و پیش‌فرض TCP، fallback SNI به hostname مقصد، و ردکردن Shadowsocks با credential ناقص.
- ابزارهای Python برای استخراج گزارش build، کنترل Patch و آزمایش Patch در کپی موقت اضافه شدند؛ گزارش runtime نیز با حذف لینک کانفیگ/UUID/credential قابل تولید است.
- CI اکنون تست‌های Dart و Python را اجرا می‌کند و در شکست، گزارش عیب‌یابی را به‌صورت artifact ذخیره می‌کند.

## مواردی که هنوز ادغام/تأیید نشده‌اند

- تولید خودکار Patch توسط مدل AI هنوز به یک provider/مجوز امن و فرایند تأیید در CI متصل نشده است. ابزار موجود Patch پیشنهادی را در کپی موقت آزمایش می‌کند و سورس نصب‌شده را درجا تغییر نمی‌دهد.
- برای اینترنت ملی، تست throughput داخلی با فایل‌های حجیم و قابل‌اندازه‌گیری هنوز نیازمند endpoint داخلی معتبر است؛ تا آن زمان سرعت ملی جعلی تولید نمی‌شود و تست بین‌المللی به‌عنوان معیار سلامت ملی استفاده نمی‌شود.
- چرخه کامل Android plugin lifecycle (foreground promotion، STOP در process جدا، receiver/EventChannel در rotation و revoke) هنوز نیازمند بازبینی و تأیید build واقعی است؛ اسکریپت فعلی بخشی از اصلاحات stop/foreground/protector را اعمال می‌کند، اما نباید آن را تأیید کامل lifecycle تلقی کرد.
- هیچ تست واقعی روی دستگاه، اپراتور ایران یا build محلی در این محیط اجرا نشده است.

- Flutter و Dart SDK در محیط کاری موجود نبودند؛ بنابراین `flutter test`، `flutter analyze` و APK build باید در GitHub Actions اجرا شوند.
