# وضعیت پیاده‌سازی King VPN — به‌روزرسانی 2026-11-20

## معماری فعلی
- مسیر تونل فعال پروژه از طریق `flutter_v2ray_client 3.5.0` و هستهٔ Xray/V2Ray اجرا می‌شود. NNIE و National Engine اجزای خلبان، تحلیل شواهد و انتخاب مسیرند، نه موتورهای تونل مستقل.
- رابط اصلی از یک کنترل اتصال خلبان برای شروع/توقف استفاده می‌کند؛ ابزارهای پروتکل و صفحات کمکی حذف نشده‌اند.
- سلامت مسیر داخلی و جهانی جداگانه ارزیابی می‌شود. شکست probe جهانی به‌تنهایی نباید مسیر داخلی سالم را رد کند.
- خودترمیم زمان اجرا باید بر شواهد data-plane تکیه کند و اجازهٔ بازنویسی فایل اجرایی Dart/Android در اپ نصب‌شده را ندارد.
- اسکن خودکار IP به endpointهای دقیق کانفیگ/حافظه محدود شده؛ اسکن گستردهٔ CIDR عمومی، همسایگی /24 و پورت‌گردی خودکار حذف شده است.
- تغییر SNI نباید اعتبارسنجی گواهی TLS را خاموش کند؛ پاسخ‌های DoH و DNS با اعتبارسنجی ساختاری بررسی می‌شوند.
- parserهای پلاگین در مرحلهٔ ساخت برای WS، VMess، VLESS، Trojan و Shadowsocks سخت‌سازی می‌شوند.
- ابزارهای Patch Gate و repair orchestrator برای آزمایش تغییرات در کپی ایزوله وجود دارند؛ این چارچوب به‌تنهایی به معنی تولید خودکار patch معتبر توسط مدل AI یا انتشار خودکار production نیست.

## انتشار رسمی
Workflow عادی، APK آزمایشی Release-mode با debug key تولید می‌کند. برای نسخهٔ production باید workflow امضای رسمی با `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD` و در صورت نیاز `KING_UPDATE_GIST_TOKEN` اجرا شود. هیچ کلید یا رمز امضایی نباید در مخزن عمومی یا سورس ZIP قرار گیرد.
